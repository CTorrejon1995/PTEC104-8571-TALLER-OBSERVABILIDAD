# Documentación

## Propósito
Mantener la memoria técnica, los diagramas, las evidencias y las referencias del proyecto.

## Responsabilidades
- `INFORME.md`: informe académico con las cuatro secciones obligatorias.
- `architecture/`: diagramas y descripción de la arquitectura.
- `evidence/`: capturas reales obtenidas durante las validaciones.
- `references/`: fuentes técnicas y bibliografía APA 7 cuando corresponda.

## Estructura
```text
docs/
├── INFORME.md
├── architecture/
├── evidence/
└── references/
```

## Dependencias
La documentación se actualizará progresivamente en cada PR. Las evidencias solo se incorporarán después de ejecutar las pruebas correspondientes.

## Ejecución y validación
Revisar que los comandos, resultados y capturas correspondan a ejecuciones reales. No se deben declarar componentes operativos sin evidencia.

## Entrega integrada

El [informe técnico](INFORME.md) reúne las cuatro secciones de la consigna y las capturas de métricas, logs, Grafana/Webhook y Jaeger. El resultado completo de Windows está en [PR05_VALIDACION.md](PR05_VALIDACION.md). El procedimiento de commit y Pull Request está en [PR05_CIERRE.md](PR05_CIERRE.md).
